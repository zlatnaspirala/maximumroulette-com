Engine Overview 01 // INTRODUCTION

The matrix-engine-wgpu is a stable, high-performance, and continually evolving WebGPU rendering platform written in Rust. Inspired by the designs of the original WebGL-based matrix-engine, it has been fully rebuilt from the ground up for the next-generation WebGPU hardware standard.

By dropping legacy gl-matrix bindings in favor of the optimized wgpu-matrix mathematical pipeline, "The Beast" handles heavy model-view-projection translations with absolute memory spatial layout maps and minimal thread latency. It compiles smoothly across native client drivers (Vulkan, Metal, Direct3D 12) or to web targets via WASM.

Architecture Specs 02 // STABLE FEATURES

The graphics core orchestrates buffers and shaders elegantly to deliver peak rendering optimization across standard desktop environments including Chrome, Edge, and Opera (Note: v1.1x.0 Firefox pipeline renders are currently undergoing active optimization).

⚡

PipelineManager Draw Loops

Sequences are bound dynamically per-pipeline rather than per-individual-mesh over a shared material index to yield power draw optimization benefits.

⚛️

Offloaded Web-Worker Physics

Built-in integrations for Ammo.js, cannonES, and Jolt Physics engines. Physics computations are performed cleanly via secondary worker threads to prevent main thread blocking.

🎬

Post Processing & Shaders

Supports Bloom Filters, Volumetric Scattering, Hierarchical Z-Buffer (HZB) passes, custom WGSL-based shadow casting on skinned rigs, and real-time viewport culling overrides.

🏔️

Procedural Morph Entities

Dynamic geometric interpolation allowing Morph-blending between procedural configurations (e.g. circles, cones, klein shells, or mobius strips) with exact shadow tracking recalculations.

FluxCodex Scripting 03 // FLOW_EDITORS

Available when executing the workspace environment directly from source using the alias npm run editorx, Nikola Lukić's platform features two dual-graph visual node environments designed for rapid prototype flows:

  • FluxCodexVertex: Interactive client execution logic graphs. Connect events, math parameters, update functions, variable popups, and track direct SceneObject reference attributes.
  • FluxCodexShader: Shader materials graph generator. Draw customizable procedural outputs with visual pipelines.
  • Audio Reactive Nodes: Hook direct frequency analysis (Low, Mid, High, Energy, Beat values) straight to object positions, scaling transforms, or vertex morph factors.
  • Experimental Ollama AI Copilot: Automates graph configurations by linking instructions straight with local Groq or Ollama neural setups.

Saved layouts are cached directly on localStorage or outputted to physical filesystem JSON descriptors, compiling to clean JS nodes injected into target runtimes.

Scene & Camera Guides 04 // MAIN CORE

The engine completely abstracts HTML boilerplates by generating the canvas interface programmatically inside memory: 

import MatrixEngineWGPU from "./src/world.js";

const app = new MatrixEngineWGPU({
  useSingleRenderPass: true,
  canvasSize: "fullscreen",
  mainCameraParams: {
    type: "WASD", // Options: WASD, RPGCamera, FirstPersonCamera, cinematicCamera
    responseCoef: 1000
  }
}, () => {
  console.log("WebGPU Ready");
});

Manipulating Camera Instances & Bounded Paths

Adjust yaw, pitch, and positional parameters directly. For cinematic cutscenes, you can orchestrate multi-point bezier curves: 

const cam = app.getCamera();
cam.setPosition(x, y, z);
cam._dirtyAngle = true; // Flag position matrix recalculation

// Cinematic Arc Splines
const path = new CameraPath([
  { position: [0, 5, 20], target: [0, 0, 0] },
  { position: [10, 12, 10], target: [0, 1, 0] }
], { parameterization: 'arc' });

cam.setPath(path).play({ speed: 0.3 });

Physics Web Workers 05 // SIMULATION

In version 1.11.0, physics bodies execute asynchronously within dedicated thread pools. To access items, use secure body IDs instead of direct element pointer variables: 

// Bind event listeners for raycasted collisions
app.canvas.addEventListener("ray.hit.event", e => {
  const physics = app.matrixPhysics;
  const bodyId = physics.getBodyByName(e.detail.hitObject.name);
  
  if (bodyId) {
    // 1. Emit instant impulse vectors
    physics.applyImpulse(bodyId, new PVector(0, 5, 0));
    
    // 2. Explode at specific ray impact positions
    const hitPoint = new PVector(e.detail.hitPoint.x, e.detail.hitPoint.y, e.detail.hitPoint.z);
    physics.explode(bodyId, hitPoint, 10, 50);
  }
});

Dynamic Light Entities 06 // RENDERING LAYERS

Unlike legacy environments where lights exist only on camera vectors, matrix-engine-wgpu decouples lighting into distinct objects that can be placed, and supports light behaviors: 

// Spawn standard light entities
app.addLight();

const light = app.getSceneLightByName("light1");
// Standard oscillation setup: setPath0 moving back/forth
light.behavior.setOsc0(-1.0, 1.0, 0.01);
app.lightContainer[0].updater.push(item => {
  item.setPosX(item.behavior.setPath0());
});

Materials & Env Mapping 07 // TEXTURES

The pipeline supports dedicated materials such as standard, pong, power, water, metal, and mirror.

Highly Configurable Water Parameters

Configure liquid depth, surface crest height, and wave travel parameters dynamically: 

// Assign deep navy to cyan water with custom wave heights and sharp specular glares
app.mainRenderBundle[0].updateWaterParams(
  [0.0, 0.1, 0.3], // Deep Color
  [0.3, 0.8, 1.0], // Shallow Color
  1.2,             // Wave speed
  2.5,             // Wave scale
  0.3,             // Wave amplitude height
  2.5,             // Fresnel reflection coefficient
  100.0            // Specular shiny factor
);

Standard Mirrored Environments

app.addGlbObj({
  material: { type: 'mirror' },
  envMapParams: {
    baseColorMix: 0.55,
    mirrorTint: [0.9, 0.95, 1.0],
    reflectivity: 0.95,
    illuminateColor: [0.3, 0.7, 1.0],
    illuminateStrength: 0.1,
    fresnelPower: 5.0,
    envLodBias: 2.5,
    usePlanarReflection: false
  }
});

Instancing & Media 08 // BUFFERS

For optimal drawing of repetitive objects, use the MEMeshObjInstances subsystem. It renders massive duplicate structures within single drawing pipelines (supports independent colors, scaling index, and movement offsets): 

// Populate mesh arrays
app.addGlbObjInstance({
  material: { type: "standard", useTextureFromGlb: true },
  scale: [20, 20, 20],
  texturesPaths: ["mutant_color.webp"]
}, null, glbBuffer);

// Translate instanced offset item dynamically
app.mainRenderBundle[1].instanceTargets[1].position[2] = 10;
app.mainRenderBundle[1].updateInstances(5); // Sync changes to buffer

Real-time Video Render Streams

You can actively pipe live HTML5 video elements, webcams, or Canvas2D context buffers straight into WebGPU texture samplers at runtime:

URL Controller Flags 10 // PARAMS

Manipulate system-level engine variables directly by passing URL search search variables at runtime. This provides key testing flexibility over mobile client performance levels:

QUERY FLAG DEFAULT VALUE FUNCTIONAL OUTCOME
?PHYSICS_GROUND_Y=[num] 0 Adjusts physical world floor vertical index
?fs=true false Forces fullscreen client overlays on initialization
?MAX_BONES=[num] RIG DEFAULT Limits bone weights (Set 0 to optimize mobile rendering)
?MAX_SPOTLIGHTS=[num] 4 Limits overall shadow spotlight configurations
?SHADOW_RES=[num] 1024 Alters shadow texture resolutions (e.g., 250 for low-end)
?GRAVITY_Y_AXIS=[num] -9.8 Overrides engine physics gravity level
